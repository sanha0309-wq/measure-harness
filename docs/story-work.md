# 작업 스토리 — 내가 지금 실측하는 방식

> 하네스가 대신할 **지금의 일하는 방식**. 어디서 시간이 새고 어디서 결과가 흔들리는지 적는다.

## 이 일이 하네스에 맞는 이유
| 조건 | 해당 여부 |
|---|---|
| 최근 3개월 안에 2번 이상 해본 일 | ✅ 한 달 동안 토스 · flex · ChatGPT · Notion 등 10곳 넘게 쟀다 |
| 매번 결과가 조금씩 달라서 불만인 일 | ✅ 문서마다 목차 · 깊이 · 토큰 파일 유무가 다르다 |
| 중간에 파일이나 문서가 남는 일 | ✅ 캡처 · 실측값 · 토큰 · 대응표가 차례로 남는다 |

## 지금 하는 순서
1. 잴 서비스와 화면을 고른다 (홈 · 목록 · 상세 · 모달 · 빈 상태 등)
2. 웹이면 브라우저 개발자 도구에서 값을 읽는다. 앱이나 로그인 화면은 캡처를 찍고 픽셀로 잰다
3. AI에게 값을 정리시켜 실측 문서를 만든다
4. 필요하면 토큰 json을 따로 만든다
5. 토큰과 컴포넌트를 HTML 디자인 시스템 페이지로 만들어 눈으로 확인한다
6. 우리 디자인 시스템 값과 비교해 바꿀 후보를 고른다
7. 며칠 뒤 다시 보다가 틀린 값을 발견하고 「정정」을 덧붙인다

## 어디서 흔들리나
- **2번:** 캡처 배율을 안 적어서, 나중에 그 값이 1배인지 1.5배인지 모른다
- **3번:** 매번 AI에게 다르게 요청해서 목차가 문서마다 다르다
- **3번:** 못 잰 값을 AI가 그럴듯하게 채워 넣는다. 추정값과 실측값이 섞인다
- **4번:** 토큰 파일을 만들 때도, 안 만들 때도 있다
- **5번:** HTML을 AI가 매번 새로 짜서, 토큰 파일에 없는 값이 페이지에 끼어들거나 형식이 서비스마다 다르다
- **7번:** 정정이 문서 끝에 덧붙어서, 본문 값과 정정 값이 함께 남는다

## 하네스가 바꿔야 할 것
- 목차는 템플릿 하나로 고정
- 모든 값에 출처 표기 — 스크립트가 센다
- 못 잰 값은 「못 잼」으로 남기고, 채워 넣지 않는다
- 토큰 · 견본 페이지 · 대응표 · 빈 칸 목록은 매번 같이 나온다
- 견본 페이지는 토큰 파일에서 스크립트로 만든다. AI가 손으로 쓰지 않는다
- 다시 재면 이전 값과 비교해 정정 목록을 따로 뽑는다

## 정해 둔 것
- **잴 화면:** run마다 자유롭게 고르고, 고른 목록을 실측 문서 §0 「잰 화면 목록」에 적는다. 서비스 간 비교는 화면 목록이 아니라 템플릿 목차로 한다
- **배율:** DOM 측정은 스니펫이 `devicePixelRatio`와 화면 폭을 함께 기록한다. 앱 캡처의 배율은 사람이 run 입력 파일에 적는다
- **DOM 수집:** 하네스에 고정된 스니펫을 사람이 개발자 도구 콘솔에 붙여 넣고, 나온 JSON을 넘긴다
- **정정:** 이번에는 「다시 재기」로 생기는 정정만 다룬다

## 비교 기준
이미 손으로 잰 실측 문서가 여러 개 있다. 같은 서비스를 하네스로 다시 재서 나란히 놓으면,
목차가 같아졌는지 · 출처 표기가 다 붙었는지 · 정정할 값을 찾았는지로 하네스가 잘 돌았는지 판단할 수 있다.
- 기준 화면: **실서비스 홈 (손으로 잰 비교 기준)** (로그인 없이 보이는 화면)
- 손으로 잰 문서: `refs/<service>-home.md` — 공개하지 않는다 (`refs/`는 .gitignore)
