# PRD — 레퍼런스 실측 하네스

> 공개 저장소용. 회사 이름 · 고객사 · 사내 디자인 시스템 실제 값은 넣지 않는다.
> 「우리 값」이 필요한 곳은 `docs/our-tokens.example.json`의 예시 값을 쓴다.

## 1. 한 줄 정의
레퍼런스 실측 하네스는 **UI 디자이너**가 **잘 만든 서비스의 화면 규격(배치 · 글자 · 색 · 간격 · 반경 · 컴포넌트)**을
**매번 같은 목차와 같은 출처 표기로** 재서, 실측 문서 · 토큰 파일 · 우리 값 대응표로 남기는 하네스다.

## 2. 주요 사용자 1명
**UI 디자이너 (나)** — 디자인 시스템을 만들면서 토스 · flex · ChatGPT 같은 서비스를 일주일에 여러 번 잰다.
지쳐 있는 것:
- 실측 문서마다 목차와 깊이가 달라서, 나중에 두 서비스를 나란히 비교하기 어렵다
- 잰 값인지, 캡처에서 추정한 값인지, 내가 정한 값인지가 섞여서 나중에 다시 확인해야 한다
- 잘못 잰 값을 뒤늦게 「정정」하는 일이 반복된다

## 3. 사용 시나리오
**A. 새 서비스 재기**
1. 서비스 이름과 화면(URL 또는 캡처)을 준다
2. 하네스가 화면별로 값을 잰다 — 웹이면 DOM(getComputedStyle), 앱이나 로그인 화면이면 캡처 픽셀
3. 정해진 목차로 실측 문서를 쓰고, 토큰 파일로 묶는다
4. 점검 스크립트가 출처 누락 · 형식 오류 · 빈 칸을 센다
5. 토큰 파일과 실측 문서에서 디자인 시스템 페이지(tokens.html — 토큰 견본 + 컴포넌트 견본)를 만들어 눈으로 확인한다
6. 우리 값과 다른 점을 표로 뽑고, 채택 후보를 표시한다

**B. 이미 잰 서비스 다시 재기 (정정)**
1. 이전 실측 문서가 있는 서비스를 다시 잰다
2. 하네스가 이전 값과 달라진 값만 「정정」 목록으로 뽑는다

## 4. 산출물 (화면 대신)
| # | 파일 | 내용 |
|---|---|---|
| 1 | `runs/<서비스>-<날짜>/measure.md` | 실측 문서 — 정해진 목차 |
| 2 | `runs/<서비스>-<날짜>/tokens.json` | 색 · 글자 · 간격 · 반경 · 그림자 · 크기 토큰 |
| 3 | `runs/<서비스>-<날짜>/compare.md` | 우리 값 대응표 · 채택 후보 |
| 4 | `runs/<서비스>-<날짜>/gaps.md` | 아직 못 잰 것 · 추정값 목록 |
| 5 | `runs/<서비스>-<날짜>/tokens.html` | 디자인 시스템 페이지 — 토큰 견본(색 · 글자 단계 · 간격 · 반경 · 그림자) + 컴포넌트 견본(measure.md §6의 버튼 · 입력 · 탭 · 배지 · 표 · 모달 · 빈 상태). **스크립트로 생성** (AI가 손으로 쓰지 않는다) |
| 6 | `runs/<서비스>-<날짜>/corrections.md` | 이전 run과 달라진 값만 — 이전 run이 있을 때만 |

- 각 파일의 형식과 run 폴더 구성은 `docs/outputs.md`

- tokens.html의 토큰 견본은 tokens.json에 있는 값만 쓴다. 견본 수 = 토큰 수.
- 컴포넌트 견본은 measure.md §6 값 칸만으로 그린다. 못 잼 · 해당 없음 칸은 그리지 않고 빈 자리로 표시한다.
- 견본마다 값과 출처 표기(§5)를 함께 보여 준다. 〔추정〕 견본은 눈에 띄게 표시한다. (〔임의〕는 measure.md에 올 수 없으므로 tokens.json에도 없다)

**run 단위**
- run 하나 = 서비스 하나 · 화면 폭 1440 하나 · 날짜 하나. 폴더는 `runs/<서비스>-<날짜>/`
- 같은 서비스를 같은 날 다시 재면 덮어쓰지 않고 `-2`, `-3`을 붙인다
- 한 run 안에 DOM 값과 캡처 값이 섞여도 된다. 값마다 출처 표기로 구분한다

## 5. 값의 출처 4가지 (모든 값에 하나가 붙는다)
| 표기 | 뜻 |
|---|---|
| `〔DOM〕` | 브라우저에서 계산된 스타일을 읽은 값. 가장 믿을 수 있다 |
| `〔픽셀 · 배율 n · ±1〕` | 캡처 이미지에서 픽셀로 잰 값. 배율과 오차를 이 형식 그대로 적는다 (예: `〔픽셀 · 배율 1.5 · ±1〕`) |
| `〔추정 · 근거〕` | 직접 재지 못하고 다른 값에서 계산한 값. 근거를 함께 적는다 |
| `〔임의〕` | 재지 않고 내가 정한 값. **measure.md에 있으면 차단.** 내가 정한 값은 compare.md의 채택 후보로만 둔다 |

## 6. 상태
**실행 상태:** 수집 중 → 정리 중 → 점검 중 → 승인 대기 → 완료
- 점검 결과는 **차단 · 경고** 두 종류. 차단이 1건이라도 있으면 승인 대기로 넘어갈 수 없다
- 단계 · 전이 조건 · 돌아갈 길은 `docs/pipeline.md`

## 7. 범위 밖
- 서비스 클론 화면 만들기 (Figma · 코드)
- 로그인이 필요한 화면에 하네스가 대신 로그인하기 — 로그인은 사람이 먼저 해 두거나 캡처로 준다
- 다크 모드 (다음 단계)
- 공식 디자인 시스템 문서 긁어오기 — 실제 화면에서 잰 값만 다룬다
- 사람이 직접 지정하는 정정 (다음 단계) — 이번에는 다시 재기로 생기는 정정만 다룬다
- 반응형 여러 폭 — run 하나에 폭 1440 하나만 잰다
- 애니메이션 · 전환 시간(motion) 실측
- 여러 서비스를 한 표로 묶는 비교 문서 — compare.md는 서비스마다 우리 값과만 비교한다
- 접근성 점검 (명도 대비 판정 등)

## 8. 조건 — 어기면 안 되는 것
- **모든 값에 출처 표기가 있다.** (§5 네 가지 중 하나)
- **〔픽셀〕 값은 배율과 함께 적는다.**
- 실측 문서 목차는 `docs/measure-template.md`를 벗어나지 않는다. 못 잰 칸은 지우지 않고 「못 잼」으로 남긴다.
- 「우리 값」은 공개용 예시 값만 쓴다. 실제 사내 값 · 회사 이름을 넣지 않는다.
- 남의 서비스 로고 · 이미지 · 문구 원문을 저장소에 올리지 않는다. 값과 구조만 적는다.
  - 문구 원문은 스크립트가 **경고**로 세고, 사람 승인 파일의 확인 항목에도 넣는다
  - 예외: 요소를 알아보기 위한 짧은 화면 문구(버튼 라벨 등)는 `label`로 둔다. 실측 문서에는 값 옆에 찍고(어느 요소인지 보이게), 토큰 파일 · 대응표에는 찍지 않는다. 길이 상한은 `rules.yaml`. 긴 본문(기사 · 설명문)은 옮기지 않는다
  - 실측 문서에 label이 찍혀도 되는 이유: 실제 서비스 run은 비공개(.gitignore)이고, 공개 run은 저장소 안의 가상 견본 페이지다
  - 캡처 이미지는 어떤 경우에도 커밋하지 않는다 (시연 run 포함)

## 9. 완료 조건과 하네스 검증 기준 — 둘은 따로다

### 9-1. 평소 run의 완료 조건
- `check.py` 차단 0 → 「승인 대기」 → `approval.md` 확인 · 서명 → `finalize.py` 통과 → 「완료」
- 평소 run에는 `refs/`가 **없다고 본다.** 어떤 run 스크립트도 refs가 없다고 실패하지 않는다
- 평소 정확도 확인은 저장소 안의 가상 견본 페이지 `fixtures/sample.html`과 정답 파일로 한다

### 9-2. 하네스 검증 기준 (R8, 1회)
하네스를 만든 뒤 한 번, 실서비스 홈 (손으로 잰 비교 기준) run을 손으로 잰 `refs/<service>-home.md`(공개하지 않음)와 나란히 놓고 센다.
별도 스크립트 `scripts/verify_refs.py`만 refs를 읽는다. 수치는 `rules.yaml`의 `refs_compare`.

| 기준 | 세는 방법 | 통과 |
|---|---|---|
| 목차 고정 | measure.md 제목 목록 vs measure-template.md 제목 목록 | 100% 일치 〔임의〕 |
| 출처 표기 | 값이 있는 칸 중 출처가 없는 칸 | 0개 〔임의〕 |
| 측정 범위 | refs에 있는 항목 중 하네스가 잰 항목 비율 | ≥ 80% 〔임의〕 |
| 정정 발견 | refs 값과 다르게 나온 항목 수 | 개수만 보고. 맞는지는 사람이 판단 〔임의〕 |

- refs는 1442 폭에서 잰 문서다. 레이아웃 폭 값은 ±2로 비교하고, 컴포넌트 값(높이 · 반경 · 색 · 글자)은 그대로 비교한다
